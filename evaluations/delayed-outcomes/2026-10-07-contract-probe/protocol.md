# Preregistro — disponibilidad temporal

Cuatro casos A–D, dos contextos CLI nuevos por caso: pautas actuales design-validation 0.1.0 como baseline y mismas pautas + contrato v0.1 como treatment. Solo cambia el suplemento. Modelo claude-sonnet-5-5, effort medium; sin herramientas, sin skills nativas, sin persistencia de sesión, safe-mode. No se modifica Foundry ni el piloto cerrado.

Inputs ficticios mínimos, no clientes reales; expected fuera de prompts. Un run por condición/caso; no reintentos por mala calidad. Orden alternado A baseline primero, B treatment primero, C baseline primero, D treatment primero. Se conservan outputs íntegros, errores y coste/duración informados.

Checks: una fila por ID, elegibilidad y label_state exactos, preguntas en D, gate NEEDS_REVIEW. Sin score compuesto ni extrapolación de mejora: una repetición y cuatro casos estrechos. Review semántico del autor no independiente. Esta es una prueba de suplemento documental, no evaluación nativa ni experimento canónico Foundry. El candidate sigue como conocimiento hasta revisión de evidencia.
